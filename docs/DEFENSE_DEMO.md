# Демонстрация CRM на защите — 7–10 минут

Сценарий относится к проверенной версии `537d298` и полностью мигрированной **отдельной синтетической БД0007**. Это инструкция показа, не текст диплома. Акт, ограничения и безопасное обновление — [9Б](FINAL_ACCEPTANCE_9B.md).

## Подготовка до начала показа

1. Получить проект в **новую отдельную папку**, выполнить [локальный запуск README](../README.md#локальный-запуск). Не использовать рабочую облачную SQLite0005. Сохранить постоянный для этой демосреды `DJANGO_SECRET_KEY` приватно; пароли/БД не публиковать.
2. Создать администратора через `createsuperuser`, затем в Admin двух активных менеджеров `demo-manager-1`/`demo-manager-2`, без staff/superuser. Пароли выбрать самостоятельно. Проверить вход обоих. Рабочие учётные записи не копировать.
3. Через интерфейс создать два вымышленных клиента: «Учебная компания Лира» и «Учебный сервис Ритм». Email при необходимости — `demo@example.invalid`. Не использовать реальные телефоны/имена.
4. Подготовить по заявке каждого менеджера; каждой автоматически соответствует одна задача. У первой срок — вчера UTC, у второй — через неделю UTC. Добавить одну ручную задачу. Часть оставить в new/in_progress для демонстрации просрочки, одну задачу завершить.
5. Подготовить пять сделок с суммами1000.00/2000.00/3000.00/4000.00/5000.00, по одной на каждый этап: новая, контакт, предложение, успех, проигрыш. Создание всегда в «Новая»; нужный этап выбрать последующим редактированием/формой Kanban. Распределить сделки между двумя менеджерами.
6. Войти поочерёдно каждым менеджером и добавить суммарно четыре взаимодействия: звонок, встреча, переписка, комментарий, с датами не позднее текущего времени. Автор назначается сервером; создание всех событий под admin не даст менеджерам собственной истории.
7. Убедиться, что `python manage.py migrate --check` и `python manage.py check` возвращают0. Сделать **приватный контрольный backup синтетической демобазы при остановленном сервере** по [процедуре9Б](FINAL_ACCEPTANCE_9B.md#database-operations), затем запустить сервер локально.

Во время приёмки цепочка реально выполнена в Chromium1440/768/375/320 с JS и без, также отдельно проверен менеджер. Для живого показа достаточно1440 px и краткого переключения на375 px. Если drag-and-drop недоступен, использовать штатную форму этапа: это полноценный поддерживаемый способ.

## Числа для примера М1

Выбрать размер **две заявки × два сотрудника**, работников в порядке создания manager-1, manager-2. α=0.5, β=0.5; занятость обоих0. Времена вводятся часами (`2:15` означает2 часа15 минут).

| Поле | Сотрудник1 | Сотрудник2 |
|---|---:|---:|
|Мощность A, часов|2|2:15|
|Начальная занятость L|0|0|
|Ставка, руб./час|100|400|
|Заявка1 «Подготовка предложения», часов|1|1|
|Заявка2 «Анализ требований», часов|2|2:15|

Ожидается **вычисленный**, а не подставленный результат: greedy назначает1→1,2→2, C=1000, U=1, T=13/4 ч, F=23/26; B&B назначает1→2,2→1, C=600, U=1, T=3 ч, F=19/26. Нормировка C₀=1300; относительное улучшение F=4/23≈17.39%. Это условный пример, не измеренная экономия предприятия. Если выбран иной набор/порядок сотрудников, проверить соответствие введённых параметров; реальные ID могут отличаться.

## Восстановление и безопасный повтор

- Перед показом закрыть лишние вкладки подтверждений. Подписанный снимок действует15 минут от расчёта; при истечении времени пересчитать. Для недоказанного полного плана нужно дополнительное явное согласие; в основном показе М1 ожидается OPTIMAL.
- При сетевом сбое после подтверждения пакет уже мог сохраниться. Повторить **тот же токен** штатной кнопкой, проверить прежние ID; не создавать новый расчёт ради повтора. После конфликта409 Kanban обновить доску и повторить с актуальной версией.
- Для сброса демо остановить все процессы, использующие **демобазу**, восстановить приватный контрольный backup по процедуре9Б, проверить integrity/FK/миграции и запустить с тем же ключом. Не сбрасывать рабочую пользовательскую SQLite. Backup и локальные пароли в Git не добавлять.
- Foreground `runserver` останавливается **Ctrl+C в его терминале**. Не запускать массовый `pkill`. Нельзя продолжать показ текущего кода на восстановленной0005: подготовленный checkpoint должен быть0007.
