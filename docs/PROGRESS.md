- CRUD: /tasks/, create, detail, edit, delete; поиск названия, фильтр статуса, две сортировки, пагинация 10, сообщения и пустые состояния. В навигации «Задачи», в карточке заявки список доступных задач. Существующий локальный CSS используется без новых зависимостей.
- Права: менеджер видит/редактирует задачу только при владении и задачей, и заявкой; создаёт по своей заявке, сервер назначает его самого, POST не может переназначить или задать completed_at. Администратор управляет всеми задачами, обязан выбрать активного ответственного, совпадающего с ответственным заявки. Задачи не создаются автоматически и не переназначаются при изменении заявки. После её переназначения оба менеджера не видят старую задачу, пока администратор не исправит назначение.
- Связи: Task.request PROTECT, assigned_to SET_NULL. Удаление заявки с задачами обрабатывается без 500 и без потери данных, GET задачу не удаляет, POST удаления разрешён только администратору с CSRF. Удаление пользователя сохраняет заявки и задачи.
