# Техническое задание: веб-ориентированная CRM-система

## 1. Назначение
Система автоматизирует регистрацию клиентов, обработку заявок, ведение сделок, назначение задач и контроль сроков в небольшой организации. Целевая аудитория — администратор и менеджеры.

## 2. Стек и архитектура
Python + Django 5.2 LTS, SQLite для локальной демонстрации, Django Templates, Bootstrap 5, минимальный JavaScript. Монолитная архитектура, серверный рендеринг, Django ORM, встроенная аутентификация. PostgreSQL возможен позже при необходимости.

## 3. Функциональные требования
- FR-01: Вход и выход пользователей; роли администратора и менеджера, проверка доступа к операциям.
- FR-02: CRUD клиентов, поиск, фильтрация; поля: ФИО/название, телефон, email, организация, примечание.
- FR-03: Регистрация и обработка заявок; клиент, тема, описание, статус, ответственный, дата и срок обработки.
- FR-04: Сделки; клиент, название, сумма, этап, ответственный; история изменения этапа при необходимости.
- FR-05: Kanban-доска сделок с переходами между этапами. В первой версии допустимо перемещение через форму; drag-and-drop — необязательное улучшение.
- FR-06: Задачи; ответственный, связанная заявка или сделка, срок, статус.
- FR-07: Автоматизация: при создании заявки автоматически создаётся задача; просроченные незавершённые задачи выделяются при просмотре.
- FR-08: Аналитика: число клиентов, заявок, сделок, задачи по статусам, суммы сделок и простая конверсия с явно описанным правилом расчёта.
- FR-09: История взаимодействий с клиентом: тип (звонок/встреча/заметка), дата, автор, комментарий.

## 4. Нефункциональные требования
- Защита форм CSRF, валидация, ORM вместо ручной конкатенации SQL, проверки полномочий на сервере.
- Интерфейс на русском языке, адаптивная базовая верстка.
- Демо-данные вымышленные, без настоящих персональных данных.
- Для ключевых сценариев — автоматические тесты и ручной чек-лист.
- Рабочий локальный запуск по README.

## 5. Приоритеты
P0: каркас, авторизация, клиенты, заявки, задачи, автоматическое создание задачи, базовая статистика.
P1: сделки, этапы, Kanban, история взаимодействий.
P2: расширенные графики, drag-and-drop, дополнительные уведомления.
При нехватке времени сокращать P2, затем P1, сохраняя P0 и время на диплом.

## 6. Демонстрационный сценарий
Администратор создаёт менеджера; менеджер добавляет клиента и заявку; система автоматически создаёт задачу; менеджер обрабатывает заявку и задачу; показатели обновляются; при наличии P1 создаётся сделка и меняется её этап.

## 7. Критерии готовности
Функции проверяются на локальном сервере, основные операции покрыты тестами, права доступа проверены, ошибки документированы, README содержит воспроизводимые инструкции. Пояснительная записка описывает только реально реализованные возможности.

## 8. Академическая добросовестность
Система разрабатывается под данное ТЗ. Сторонние репозитории — ориентиры, а не исходный код проекта. Источники и использованные зависимости документируются. Текст диплома, схемы, измерения и выводы должны соответствовать собственному результату и правилам вуза.
