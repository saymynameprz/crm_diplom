## Детали аналитической проверки — PASS

- Конверсия: won/(won+lost)×100 при положительном знаменателе, ROUND_HALF_UP до одного знака; иначе None/«Нет данных». В выполненных тестах: 3/5→60,0%; 1/16→6,3%; отсутствие закрытых отличается от 0,0% при наличии только проигранных.
- Сумма читается только для доступных успешных сделок, складывается Decimal последовательно без SQL SUM; проверяются диапазон, конечность и масштаб. Тест 0,01+0,02 подтвердил 0,03; сумма с 9999999999,99 — 10000000000,02. При повреждённом доступном значении недоступен весь итог, без частичной суммы. Повреждённые чужие суммы не ломают отчёт менеджера. SQLite может преобразовать 1.234 в 1.23 до валидатора; этот предел не скрыт. Платежей нет, сумма не названа фактической выручкой.
- Все записи ограничиваются моментом at; последние 30 суток включают нижнюю границу. Пользовательский диапазон задаётся в UTC от начала первой даты до начала дня после последней, дополнительно исключается будущее после at. Сделки — по created_at, взаимодействия — по occurred_at. Текущие заявки/задачи и их просрочка не фильтруются периодом. Просрочка проверяется через прежний with_overdue(at): due_at<at, незавершённый статус; равенство срока моменту расчёта не является просрочкой.
- Слой представления получает готовый отчёт, вычисляет только визуальные доли и не подменяет формулы. Ошибочный период скрывает периодные метрики без ложных нулей; текущая нагрузка остаётся доступна. История взаимодействий редактируема, не выполняет звонки или отправку писем.
